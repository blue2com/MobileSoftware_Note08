# 📦 학생 배포용 모듈 가이드 (어떻게 전달할 것인가?)

학생들에게 실습용 `note08` 모듈을 배포하는 방법은 크게 두 가지 방식이 있습니다. 수업 목표와 학생들의 수준에 맞춰 선택하시면 됩니다.

---

## 🚀 방법 1: "완성된 모듈" 전체 제공 후 코드 분석 (추천)
코드를 모두 작성해 둔 현재 상태 그대로 배포하고, 슬라이드(v2)로 구조를 설명한 뒤 각자 코드를 실행 및 분석하게 하는 방식입니다.
**최근 Hilt, Room 등 설정이 복잡한 최신 라이브러리 강의에서 가장 많이 쓰이는 방식입니다.**

### 장점
* 설정(build.gradle) 오류나 오타로 인해 진도가 지연되는 것을 방지합니다.
* 전체 아키텍처(구조)와 데이터의 흐름(Flow)을 넓은 시야에서 이해하는 데 집중할 수 있습니다.

### 추천 배포 방식 (Git 사용)
가장 깔끔한 방법은 GitHub 저장소를 활용하는 것입니다.
1. 강사님의 GitHub에 현재 완성된 프로젝트를 **Public Repository**로 업로드합니다.
2. 학생들에게 GitHub 링크를 주고 `git clone` 으로 전체 프로젝트를 다운받게 합니다.
3. (선택) `starter` 브랜치에는 뼈대만 남기고, `main` 브랜치에 완성본을 올려 학생들이 필요할 때 정답을 확인할 수 있게 합니다.

---

## 🛠 방법 2: "빈 껍데기(Skeleton)" 배포 후 실습 진행 (전통적 방식)
UI 껍데기와 패키지 구조(폴더)만 만들어 둔 채, 핵심 로직(Room 설정, Hilt 모듈, ViewModel 등)은 비워두고 배포하는 방식입니다.
수업 시간에 핵심 코드를 학생들이 직접 채워 넣습니다.

### 장점
* 직접 타이핑하며 세부적인 문법과 어노테이션(`@Inject`, `@Dao` 등)을 확실하게 익힐 수 있습니다.

### 이 방식을 선택할 경우 비워두어야 할 핵심 파일들 (TODO 주석 처리)
학생들에게 배포하기 전, 아래 파일들의 핵심 로직을 지우고 `// TODO:` 주석을 남겨둡니다.

1. **`build.gradle.kts`**: Hilt, Room 플러그인 및 의존성 주석 처리
2. **`TodoDao.kt`**: `@Query`, `@Insert` 등의 쿼리문과 함수 내부 비워두기
3. **`AppModule.kt`**: `@Provides` 함수 내부 비워두기
4. **`TodoViewModel.kt`**: Flow 변환(`stateIn`) 로직 및 코루틴(`viewModelScope.launch`) 블록 비워두기

---

## 💡 결론 및 강사님을 위한 팁

만약 학생들의 안드로이드 경험이 많지 않다면 **방법 1 (완성본 배포)**을 강력히 추천합니다. 

Hilt나 Room 설정은 단 한 줄의 오타(`kapt` 설정 누락 등)만으로도 알 수 없는 빌드 에러를 뿜어내어 수업 분위기가 어수선해지기 쉽습니다. 완성본을 배포한 후 주석을 함께 달아주며 코드를 읽게 하고, **"새로운 기능(예: Todo 항목에 '마감일' 추가하기)을 스스로 구현해 보세요"** 라고 과제를 주는 것이 훨씬 교육 효과가 높습니다.
